1. Introduction to Web Services

Web Services are software systems that allow different applications to communicate and exchange data over a network. They enable communication between applications developed using different programming languages and running on different platforms.

Web services commonly use standard web technologies such as XML, HTTP, SOAP, WSDL and UDDI to exchange information.

Features of Web Services

  • Interoperability: Applications developed using different technologies can communicate with each other.
  • Platform Independent: They can work across different operating systems and platforms.
  • Reusability: A web service can be used by multiple applications.
  • Loose Coupling: The client and service are independent of each other's internal implementation.
  • Standard Protocols: They use common standards such as HTTP, XML and SOAP.

2. UDDI (Universal Description, Discovery and Integration)

UDDI stands for Universal Description, Discovery and Integration. It is a standard that provides a directory where businesses and organizations can publish information about their web services. Other applications can search this directory to find available services.

UDDI helps service providers publish their services and allows service users to discover and access them.

Main Components of UDDI

  • White Pages: Contains basic information about a business, such as its name, address and contact details.
  • Yellow Pages: Organizes businesses and services according to categories and industries.
  • Green Pages: Provides technical information about services, including how to access them.

Working of UDDI

  1. A service provider publishes information about its web service in the UDDI registry.
  2. A service user searches the registry for the required service.
  3. The user obtains the service description, usually through WSDL.
  4. The application connects to the service and uses it.

3. SOAP (Simple Object Access Protocol)

SOAP stands for Simple Object Access Protocol. It is a messaging protocol used for exchanging structured information between applications over a network. SOAP commonly uses XML to format messages and can work over protocols such as HTTP.

It allows applications developed using different programming languages and platforms to communicate with each other.

Structure of a SOAP Message

  • Envelope: The root element that identifies the XML document as a SOAP message.
  • Header: Contains additional information such as authentication and message routing details. It is optional.
  • Body: Contains the actual request or response information.
  • Fault: Provides error information when a SOAP message cannot be processed. It appears inside the body.

Advantages of SOAP

  • Platform and language independent.
  • Uses XML for structured message exchange.
  • Supports security and reliable messaging extensions.
  • Can operate over multiple transport protocols.

4. WSDL (Web Services Description Language)

WSDL stands for Web Services Description Language. It is an XML-based language used to describe the functions, operations, input parameters, output messages and communication protocols of a web service.

It helps client applications understand how to communicate with a web service without knowing its internal implementation.

Main Elements of WSDL

  • Types: Defines the data types used by the web service.
  • Message: Describes the data exchanged between the client and the service.
  • PortType: Defines the operations provided by the web service.
  • Binding: Specifies the communication protocol and message format.
  • Port: Defines the network address of a service endpoint.
  • Service: Groups related endpoints of the web service.

Importance of WSDL

  • Describes how a web service works.
  • Provides information about available operations.
  • Defines input and output message formats.
  • Helps clients connect to web services correctly.

5. Web Service Architecture

Web Service Architecture defines how different components interact to provide and use web services. It mainly consists of three roles: Service Provider, Service Requester and Service Registry.

Main Components

  • Service Provider: Creates and provides the web service.
  • Service Requester: The client application that searches for and uses the web service.
  • Service Registry: A directory where service providers publish service information and requesters discover services.

Three Main Operations

  1. Publish: The service provider publishes service information in the registry.
  2. Find: The service requester searches the registry to find the required service.
  3. Bind: The requester connects to the service provider and uses the service.

Technologies Used

  • SOAP: Used for exchanging messages.
  • WSDL: Used for describing web services.
  • UDDI: Used for publishing and discovering web services.
  • XML: Used for representing structured data.
  • HTTP: Commonly used for transferring messages.

6. Developing and Deploying Web Services

Developing a web service involves creating a software component that provides specific functionality over a network. Deploying a web service means making it available on a server so that client applications can access it.

Steps in Developing Web Services

  1. Define Requirements: Identify the purpose and functions of the service.
  2. Design the Service: Define its operations, input and output data.
  3. Implement the Service: Write the program using a suitable programming language and framework.
  4. Create Service Description: Prepare a WSDL document describing the service.
  5. Test the Service: Check whether all operations work correctly.

Steps in Deploying Web Services

  1. Choose a suitable web server or application server.
  2. Install and configure the required software.
  3. Deploy the web service application on the server.
  4. Configure the service endpoint and network access.
  5. Publish the service information if a registry is being used.
  6. Test the deployed service from a client application.

7. Introduction to AJAX

AJAX stands for Asynchronous JavaScript and XML. It is a web development technique used to exchange data with a server without reloading the entire web page.

AJAX allows web pages to update only the required part of their content. Although XML is included in its name, AJAX can also exchange data in formats such as JSON and plain text.

Components of AJAX

  • HTML and CSS: Used to create and style the web page.
  • JavaScript: Controls the AJAX process and updates the page.
  • XMLHttpRequest or Fetch API: Used to send requests and receive responses from the server.
  • Server: Processes requests and sends data back to the browser.
  • Data Format: Data can be exchanged using JSON, XML, HTML or plain text.

Working of AJAX

  1. The user performs an action on a web page.
  2. JavaScript sends an asynchronous request to the server.
  3. The server processes the request.
  4. The server sends a response to the browser.
  5. JavaScript receives the response and updates the required part of the page.

8. Improving Web Page Performance Using AJAX

AJAX improves web page performance by allowing data to be exchanged with the server in the background. Instead of refreshing the entire page, only the required section is updated.

Ways AJAX Improves Performance

  • Partial Page Updates: Only the necessary part of a page is refreshed.
  • Reduced Data Transfer: The browser can request only the required information instead of downloading the entire page again.
  • Asynchronous Communication: Users can continue interacting with the page while a request is being processed.
  • Faster User Interaction: It supports features such as live search suggestions and dynamic form validation.
  • Reduced Server Load: Efficient requests can avoid repeatedly generating and transferring complete pages.

Examples of AJAX

  • Live search suggestions while typing.
  • Loading new messages in a chat application.
  • Updating shopping cart details without refreshing the page.
  • Displaying notifications dynamically.
  • Checking form data in the background.

9. Programming in AJAX

AJAX programming involves using JavaScript to send asynchronous requests to a server and process the response without reloading the web page. The XMLHttpRequest object is traditionally used for this purpose. Modern applications can also use the Fetch API.

Basic Steps of AJAX Programming

  1. Create an XMLHttpRequest object.
  2. Open a connection to the server using the open() method.
  3. Define a callback function to handle the response.
  4. Send the request using the send() method.
  5. Update the web page using the received response.

Example of AJAX Using JavaScript


function loadData() {
    let xhttp = new XMLHttpRequest();

    xhttp.onreadystatechange = function() {
        if (this.readyState == 4 && this.status == 200) {
            document.getElementById("result").innerHTML =
                this.responseText;
        }
    };

    xhttp.open("GET", "data.txt", true);
    xhttp.send();
}

In this example, JavaScript sends a GET request to the server to retrieve data from data.txt. When the response is successfully received, the content of the element with the ID "result" is updated without reloading the entire page.

Important XMLHttpRequest Properties

  • readyState: Represents the current state of the request.
  • status: Contains the HTTP status code returned by the server.
  • responseText: Contains the response as text.
  • responseXML: Contains the response as an XML document when applicable.

AJAX Ready States

  • 0 - UNSENT: The request has not been initialized.
  • 1 - OPENED: The request has been opened.
  • 2 - HEADERS_RECEIVED: The response headers have been received.
  • 3 - LOADING: The response is being received.
  • 4 - DONE: The request has been completed.

10. CORBA (Common Object Request Broker Architecture)

CORBA stands for Common Object Request Broker Architecture. It is a standard developed by the Object Management Group (OMG) that allows software objects written in different programming languages and running on different platforms to communicate with each other.

CORBA uses an Object Request Broker (ORB) to manage communication between client and server objects. The ORB hides the details of network communication and allows objects to request services from other objects.

Main Components of CORBA

  • Object Request Broker (ORB): Acts as a communication manager between client and server objects.
  • IDL (Interface Definition Language): Defines the interfaces and operations provided by an object.
  • Client: Requests services from a remote object.
  • Server Object: Provides the requested services.
  • Object Adapter: Connects server objects with the ORB and helps manage their activation.

Working of CORBA

  1. The client requests an operation from a remote object.
  2. The ORB receives the request and locates the required object.
  3. The request is transferred to the server object.
  4. The server object executes the requested operation.
  5. The result is returned to the client through the ORB.

Advantages of CORBA

  • Supports communication between different programming languages.
  • Provides platform-independent communication.
  • Supports distributed applications.
  • Hides the complexity of network communication.
  • Allows software components to be reused.

Applications of CORBA

  • Distributed enterprise applications.
  • Banking and financial systems.
  • Telecommunication systems.
  • Large-scale distributed software systems.

Important Revision Points

  • Web Services: Enable communication between applications over a network.
  • UDDI: Used to publish and discover web services.
  • SOAP: XML-based messaging protocol.
  • WSDL: Describes the operations and communication details of a web service.
  • Web Service Architecture: Consists of service provider, service requester and service registry.
  • AJAX: Allows asynchronous data exchange without reloading the entire page.
  • XMLHttpRequest: Used to send and receive data asynchronously.
  • CORBA: Enables communication between distributed objects using ORB.
